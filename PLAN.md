# Current plan and handoff

**Ready to start · Pre-alpha 0.8 · Franchise pages**

A collector can already assign a game and a book to the same franchise. The next outcome is to select that franchise in Page Editor and save an introduction. After restarting Hoarder, the franchise name on either item's Explorer page should open the same introduction with both member titles and types. See the [0.8 checklist and release demo](ROADMAP.md#08-franchise-pages).

## Implementation starting points

1. The [Franchise model](backend/app/db/models/reference.py) and [item association](backend/app/db/models/links.py) already store franchise names and membership. The first missing piece is a saved introduction for an existing franchise. Implement its storage and API, then reopen it on a fresh collection and a 0.7 collection with existing game and book associations.
2. The [New Page Wizard](frontend/src/pages/PageEditor/PageEditorWizard/PageEditorWizardSteps.tsx) already lists **Franchise page**. Enable it and let the collector select a franchise by name using the [reference API](backend/app/routers/reference.py). Reopening the same franchise in Page Editor should load its saved introduction. Verify save and cancel.
3. Add the page to Explorer's [authored-page list](frontend/src/components/Explorer/explorer_pages/AuthoredPages.tsx) and link it from the franchise name on the [item page](frontend/src/components/Explorer/explorer_pages/ItemPage/ItemView.tsx). Query current membership and show each title and type. Open a member and use Back. Retain the introduction if the member list becomes empty.
4. Run the 0.8 release demo with a disposable game and book assigned to one franchise. Open the page from both items, edit the introduction and restart Hoarder. Remove the book's association and verify that its own item page still opens and the franchise lists just the game. Run the backend, frontend, build and contract checks in [AGENTS.md](AGENTS.md).

## Decisions to carry forward

| Decision | Reason |
| --- | --- |
| Owner decision · Keep the Explorer Stop, Search, Favorites and icon-only toolbar buttons, Explorer Close, and Collection Manager Minimize, Maximize and Close visible. | Their actions are planned for later. The controls are disabled until those actions are implemented. |
| Implemented during the refactoring review · Reserve catalog item numbers in SQLite when creating an item. On upgrade, start above the highest existing item. | An Explorer address remains tied to one item after deletion. Upcoming article links can rely on the same identity. Older databases have no record of numbers retired before this upgrade. |
| Owner priority, 2026-11-21 · Build rich collections and custom pages first. Schedule marketplace tracking later. | The pre-alpha demo should let someone explore a collection they authored. |
| Implemented in 0.5 · A recorded copy makes the item owned. Without copies, the collection uses the stored flag. | Older records keep their original flag, including an unset value. The Owned filter can find both manually marked items and individually recorded copies. |
| Implemented in 0.5 · Reserve each copy number for the lifetime of its item and reuse the submission ID when retrying a create. | A lost response can be retried, and delayed edits or removals cannot affect a replacement copy. |
| Owner decision · Keep Explorer item pages read-only. Show Collection Manager beside Copy Editor and confirm before switching away from a changed copy. | Collectors can browse the list while editing, keep their search and filters when switching items, and choose whether to discard a draft. Explorer’s Edit menu and toolbar open the same layout for the displayed item. |
| Implemented in 0.5 · Table and Mini pages show a count of recorded copies, with `-` for zero. Table column choices are saved in the browser. | A collector can distinguish a manually marked item from one with recorded copies and see the same Table columns in Explorer and Copy Editor. |
| Implemented on owner request · Save multiple photos and their optional descriptions with a new or existing copy. Show the filename, copy number and description in Media Viewer. | A collector can document several details of the same copy and recognize each image when browsing the collection's media. |
| Owner direction · Let collectors add custom blocks, choose page themes and arrange the sections on an item page. | A collector can decide how to present an individual item alongside the facts recorded about it. |
| Implemented in 0.6 · Store a text block followed by an optional item link. Keep the target’s catalog number and resolve its display title when reading the article. | Stable block IDs and saved order let later editors move a block or edit one of two galleries independently. |
| Implemented in 0.7 · Append one gallery after the text and optional link. Store the ordered paths from the media listing and keep gallery captions with the entries. | Reusing a photo shares its original file while allowing a caption specific to the article. Appending the gallery preserves the order of existing article blocks. |
| Proposed for 0.8 · Use the existing franchise ID for one authored page and its Explorer address. Use the franchise name as the page title and store an introduction separately from the reference description. | Existing item associations can lead to the same page. A reference entry can keep its description when its authored introduction is edited. |
| Proposed for 0.9 · Add a Layout tab beside the item properties. Use the same renderer for its preview and the read-only Explorer page. Save section placement and a page theme with the layout. | The [current item view](frontend/src/components/Explorer/explorer_pages/ItemPage/ItemView.tsx) supplies a default for older items. Built-in sections can read live catalog data wherever they appear. A per-page theme can travel with the collection independently of the browser’s [desktop appearance](frontend/src/config/appearance.ts). |
